# tern 计划 5 · 同步 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 同步任务可用：SFTP、rsync over SSH、WebDAV 三种协议，推和拉两个方向，多组文件夹对，镜像防误删，试运行。

**Architecture:** `synccore` 持有与协议无关的全部逻辑：按文件夹对执行、镜像保护、试运行。`rclone` 和 `rsync` 两个包各实现一个 `synccore.Planner`，只负责把一组文件夹对翻译成子进程调用并解析输出。`syncengine` 按协议挑选 Planner 并注册到引擎注册表。这样防误删的规则只有一份，用假 Planner 就能测透。

**Tech Stack:** Go 1.26、rclone 1.76.0、rsync（Alpine 3.24 软件源）、OpenSSH 客户端，都是子进程。

**Spec:** `2026-11-10-nas-backup-sync-design.md` §7、§8 第 2、3、5 条。执行者同时读 `docs/superpowers/plans/2026-11-10-tern-0-index.md`。

## Global Constraints

索引第 2 节全部适用。本计划另加：

- 模式与命令：`keep`（只增改不删除）→ `rclone copy` / rsync 不带 `--delete`；`mirror`（镜像）→ `rclone sync` / rsync 带 `--delete`。
- rclone 固定参数，按此顺序：`--config <运行目录>/rclone.conf --use-json-log --log-level INFO --stats 2s --timeout 60s --contimeout 15s --retries 3 --low-level-retries 10 --skip-links --create-empty-src-dirs`
- rsync 固定参数，按此顺序：`-aHs --no-inc-recursive --partial-dir=.tern-partial --timeout=60 --info=progress2 --stats`，然后 `--out-format=%i %n%L`，然后 `-e` 和 `ssh -F "<ssh_config 路径>"`。
- 路径写法：rclone 远端 `remote:<Remote>`；rsync 远端 `tern-target:<Remote>/`；rsync 的源和目的都以 `/` 结尾（同步目录的内容）。
- 镜像删除上限默认 100 个文件。只数文件，不数目录。
- 协议提示语（界面逐字使用）：`大文件多、网络差，优先选 rsync。`
- 单元测试用假的 `rclone`、`rsync` 可执行文件（做法同计划 4 的 `fakeRestic`）。真工具只出现在生成夹具的步骤和任务 5。

## Review Focus

1. **文件名含空格、中文、前导 `-`、换行** → 三种协议都能同步，试运行的删除计数准确。（任务 2、3、5）
2. **同一任务里的文件夹对互相嵌套**（把 `/s/a` 和 `/s/a/sub` 分别同步到不同地方）→ 保存时拒绝。（任务 4）
3. **源里有循环符号链接或指向目录外的链接** → 不跟随，运行不失败也不挂住。（任务 5）
4. **拉取的落地目录不存在**（挂载漏了）→ 这组失败并提示检查挂载。绝不自动创建，否则数据会写进容器可写层，重建即丢。（任务 1）
5. **一次要删或要传十万个文件** → 计数准确，清单只保留前 1000 条，内存不随文件数增长。（任务 1、2、3）

- Produces:

```go
type SourceState int
const ( SourceOK SourceState = iota; SourceEmpty; SourceMissing )

const PlanListCap = 1000
type Plan struct {
    TransferCount, DeleteCount int
    Bytes     int64
    Transfers []string // 最多 PlanListCap 条
    Deletes   []string // 最多 PlanListCap 条
}
func (p *Plan) AddTransfer(path string, size int64) // 计数总是加；清单到上限后不再追加
func (p *Plan) AddDelete(path string)

type Planner interface {
    Prepare(ctx context.Context, env engine.Env) error // 幂等：打开访问物料，写好配置文件和过滤文件
    RemoteState(ctx context.Context, env engine.Env, p model.FolderPair) (SourceState, error) // 只在拉取时调用
    Plan(ctx context.Context, env engine.Env, p model.FolderPair) (Plan, error)               // 工具自己的 dry-run
    Transfer(ctx context.Context, env engine.Env, p model.FolderPair, maxDelete int) (model.UnitResult, error) // maxDelete < 0 表示不带删除
    Describe(p model.FolderPair) string
    Close() error
}

func New(t model.Task, req engine.Request, p Planner,
    check func(context.Context) error,          // 连接预检，即 AccessOpener.Check
    mounted func(string) (bool, error)) *Engine // *Engine 实现 engine.Engine 和 io.Closer
```

`Engine` 的行为：

- `Units()`：每组文件夹对一个名字。推：`<Local> → <Remote>`；拉：`<Remote> → <Local>`。
- `Preflight`：`check(ctx)`，然后 `Planner.Prepare`。
- `Cleanup`：什么都不做。`Close`：`Planner.Close`。`Describe`：每组一行 `Planner.Describe`。
- `RunUnit(i)`，严格按下面的顺序。任何一步返回错误，后面的步骤都不执行：

1. **本机一侧。** 推：`Local` 不存在或不是目录 → `KindConfig`，`local source missing: <路径>`。拉：`Local` 不存在、不是目录、或 `mounted(Local)` 为假 → `KindConfig`，`local target missing or not on a mounted volume: <路径>`。
2. **镜像的源检查**（仅 `DeleteMode == "mirror"`）。推：读 `Local` 的目录项，一个都没有 → 空。拉：`Planner.RemoteState`，它返回的错误原样上抛。源为空或不存在 → `KindGuard`，`source is missing or empty; mirror aborted, destination untouched`。
3. **计划**（镜像模式，或 `req.Kind == "dry_run"`）。`Planner.Plan`，把结果写进 `env.Log`：每条 `would transfer: <路径>` 或 `would delete: <路径>`；清单被截断时补一行 `… and <N> more`；最后一行 `plan: <TransferCount> to transfer, <DeleteCount> to delete`。
4. **试运行到此为止。** `req.Kind == "dry_run"` → 返回 `success`，`Files` 为 `TransferCount`，`Bytes` 为 `Plan.Bytes`。
5. **删除上限**（仅镜像模式）。`DeleteCount > MaxDeletes` 且 `!req.AllowDeletes` → `KindGuard`，`would delete <N> files (limit <M>)`。
6. **传输。** `keep` → `Transfer(…, -1)`。`mirror` → `Transfer(…, Plan.DeleteCount)`，把数出来的数量交给工具自己的 `--max-delete` 当第二道闸。

`Args` 的结果：子命令（`copy` 或 `sync`）、源、目的、固定参数，然后按此顺序追加可选项：`--transfers <Transfers>`（总是有）、`--bwlimit <LimitKiB>Ki`（大于 0 时）、`--checksum`（`Compare == "checksum"` 时）、`--filter-from <文件>`（有排除规则时）、`--dry-run`、`--max-delete <N>`（`sync` 且 `maxDelete >= 0` 时）。推：源是 `<Local>`，目的是 `remote:<Remote>`；拉相反。

|---|---|

Planner：
- `Prepare`：第一次调用时 `Access.Open`、`WriteConfig`、写过滤文件（`filter.ToRclone`）；之后的调用直接返回。WebDAV 密码已由 `Access.Open` 登记到脱敏器。
- `RemoteState`：`rclone lsf remote:<Remote> --config <conf> --max-depth 1 --timeout 60s --contimeout 15s`。退出 3 → `SourceMissing`；退出 0 且 stdout 为空 → `SourceEmpty`；退出 0 有输出 → `SourceOK`；其他按 `ExitKind`。
- `Plan`：`Args(…, dryRun=true, maxDelete=-1)`，stderr 逐行喂 `Parser`。
- `Transfer`：`Args(…, dryRun=false, maxDelete)`。`UnitResult` 的 `Bytes`、`Files` 取 `Totals()`。
- rclone 的日志在 stderr。解析规则：带 `stats` 对象的行 → 进度（`bytes`、`totalBytes`、`speed`、`eta`、`transfers`、`totalTransfers`）；带 `skipped` 字段的行 → 值为 `copy` 或以 `update` 开头算一次传输，值为 `delete` 算一次删除，其余忽略；`object` 是路径，`size` 是字节数。

```go
type Deps struct { Access engine.AccessOpener; Bin string /* 默认 "rsync" */ }
func NewPlanner(t model.Task, conn model.Connection, d Deps) synccore.Planner // conn 只用于 Describe（任务 4）
```

`Args` 的结果：固定参数，然后按此顺序追加可选项：`--delete` 和 `--max-delete=<N>`（`mirror` 且 `maxDelete >= 0` 时）、`--bwlimit=<LimitKiB>`（大于 0 时）、`--checksum`、`--exclude-from=<文件>`、`--dry-run`；最后是源和目的。推：`<Local>/` 和 `tern-target:<Remote>/`；拉相反。

退出码。先看 `ClassifyStderr`：它认出 `host_key`、`auth`、`config` 就直接用；否则查表：

| 码 | 结果 |
|---|---|
| 0 | 成功 |
| 24 | 单元 `warning`（传输途中源文件消失） |
| 23 | `data`（部分文件失败） |
| 25 | `guard`（超过 `--max-delete`） |
| 1、2、3、4、5、6 | `config` |
| 10、12、30、35、255 | `network` |
| 其他非零 | `unknown` |

解析规则（stdout）：
- 进度行，形如 `    1,238,099  42%   14.98MB/s    0:00:07 (xfr#5, to-chk=169/396)`：已传字节去掉千分位；总量 = 已传 ÷ 百分比，四舍五入；速度单位 `kB/s`、`MB/s`、`GB/s` 都是 1024 进制；剩余时间 `h:mm:ss`；`to-chk=a/b` 给出 `FilesTotal = b`、`FilesDone = b − a`。
- 条目行（来自 `--out-format`）：以 `*deleting` 开头且路径不以 `/` 结尾 → 一次删除；前两个字符是 `<f` 或 `>f` → 一次传输；其余忽略。路径里的 `\#ooo`（八进制）还原成对应字节。
- 统计行：`Number of regular files transferred: N`、`Literal data: N bytes`、`Total transferred file size: N bytes`（试运行时用它作 `Plan.Bytes`）。数字可能带千分位。

Planner：
- `Prepare`：`Access.Open`，写排除文件（`filter.ToRsync`）。
