## 2. 全局约束

每份计划的每个任务都默认包含这一节。

**平台与结构**
- Docker 部署，支持 amd64 和 arm64。一个容器、一个进程、一个端口（默认 8080）。
- 安全稳定优先，性能不优先；任务数量在十几个以内。
- 传输只调用 restic、rclone、rsync、OpenSSH 子进程，不自己实现传输协议。
- 界面的所有操作只通过 `/api/v1`。所有对象有稳定的唯一 ID 和版本号。运行记录只追加，带单调递增的序号。

**版本**
- Go：`go.mod` 写 `go 1.26`。Node ≥ 26（只在构建期用）。
- restic 0.19.1、rclone 1.76.0：在 `deploy/fetch-tools.sh` 里写死版本和 SHA256，下载后校验，不符即构建失败。
- rsync、openssh-client：来自 Alpine 3.24 软件源。
- Go 依赖白名单：标准库、`modernc.org/sqlite`、`golang.org/x/crypto`、`github.com/robfig/cron/v3`。要加别的先问人。
- 前端依赖白名单见计划 6。

**凭据（对应规格 §2.3 第 3 条、§9.3）**
- 凭据指：SSH 私钥、私钥口令、WebDAV 密码、restic 仓库密码、保险箱口令、管理员密码。
- 不出现在命令行参数里；不写到持久化磁盘（需要落文件时只写 tmpfs 运行目录，权限 0600，用完即删）；日志过脱敏；不注入前后置命令的环境变量；任何接口响应都不返回。
- 加密：XChaCha20-Poly1305；口令派生和密码哈希：Argon2id（time=3，memory=64 MiB，threads=4，输出 32 字节）。
- 每条密文绑定所属记录：AAD 写作 `<表名>/<记录ID>/<字段名>`。
- SSH 只支持密钥认证。主机指纹人工确认后固定，不符即拒绝，绝不自动接受。

**数值（照抄规格）**
- SSH 保活：15 秒一次，连续 4 次无响应判定断线。
- 任务级重试：默认 3 次，间隔 1 分钟、5 分钟、15 分钟。
- 取消：先 SIGTERM，30 秒后 SIGKILL。
- 前后置命令超时：默认 10 分钟。
- 全局同时运行的任务数：默认 1。
- 多久没成功算异常：默认按计划周期的 2 倍。
- 结果状态恰好七种：`success` 成功、`warning` 完成但有警告、`partial` 部分失败、`failed` 失败、`canceled` 已取消、`skipped` 已跳过、`interrupted` 被中断。

**约定**
- 环境变量前缀 `TERN_`（`PUID`、`PGID`、`TZ` 除外）。
- JSON 字段一律 snake_case；时间一律 RFC 3339 UTC；数据库里时间存 Unix 秒。
- 接口错误体：`{"error":{"code":"<稳定英文标识>","message":"<英文>","fields":{"<字段>":"<错误码>"}}}`。界面按 `code` 显示中英文案。
- 界面中英双语。进程日志和错误 `message` 用英文。
- `go test ./...` 不依赖外部工具和网络。需要真实工具的测试带 `integration` 构建标签，用 `make itest` 在 compose 环境里跑。
- 每个任务一个提交，Conventional Commits 格式。

## 5. 我替你做的决定

规格 §15 留给实现者的，加上规格没说而计划必须定下来的。有不同意的告诉我，改起来都只动一两个任务。

1. 拆成七份计划，严格按顺序执行。
2. 工具名、Go module 名用 `tern`，环境变量前缀 `TERN_`。
3. HTTP 路由用 Go 标准库；Go 依赖只有 SQLite 驱动、x/crypto、cron 表达式解析。
4. Argon2id 参数 time=3、memory=64 MiB、threads=4。管理员密码至少 10 个字符。
5. 会话空闲 24 小时或总计 7 天后过期。登录失败按来源 IP 计数，5 次后锁 1 分钟，之后每错一次翻倍，15 分钟封顶。
6. 私钥交付用进程内 ssh-agent（unix socket 放在 tmpfs），私钥不落任何文件。三个引擎共用同一份临时 `ssh_config`，rclone 的 SFTP 也走外部 `ssh`。
7. 运行目录默认 `/dev/shm/tern`。启动时校验它确实是 tmpfs，不是就拒绝启动。
8. 指纹探测和预检用 Go 的 SSH 库（只握手，不传数据），为的是拿到确定的错误类型。
9. 错误分七类：`network`、`unknown` 会重试；`auth`、`host_key`、`config`、`data`、`guard` 不重试。判断不了的归 `unknown`，按可恢复处理。
10. “默认 3 次”理解为 3 次重试，即最多 4 次尝试。最长运行时间把重试等待也算在内。
11. 运行记录的序号在进入终态时分配。`success` 和 `warning` 都算“成功过”。
12. 试运行、恢复、清理、校验不执行前后置命令。清理和校验是独立的运行记录，失败不影响备份本身的状态。
13. 镜像删除上限默认 100 个文件。先用工具的 dry-run 数清楚再决定放不放行；真跑时把数出来的数量再传给工具当第二道闸。
14. 备份的源目录为空也算失败（规格只对同步说了这条）。空挂载点备份出空快照，保留策略会把好快照轮换掉。
15. 拉取的落地目录、恢复的目标目录必须已经存在于挂载卷里。恢复目标必须是空目录或新目录，第一版不提供覆盖。
16. 排除规则只收两种写法：不含 `/` 的名字规则（`*.tmp`）、以 `/` 开头的锚定规则（`/cache/`）。其余写法保存时拒绝。
17. rclone 一律跳过符号链接；rsync 把链接原样保留为链接。
18. 备份快照打 `tern-<任务ID>` 标签，保留策略只作用于带这个标签的快照。
19. 运行记录和日志默认保留 90 天且每任务最多 200 次。单次日志封顶 64 MiB。
20. 前端用 Tailwind 加 Radix 原语自己封装，不引整套组件库。视觉按 `DESIGN-notion.md`，只新增一个 `danger` 红色。第一版只有浅色。
21. 基础镜像 Alpine 3.24。默认以 root 运行并只保留 6 项内核能力；设了 `PUID`/`PGID` 就整体降权到那个用户。
22. 密钥文件模式要求 `/secrets` 确实是挂载卷，否则向导拒绝。`/data` 没挂载时向导整个拒绝。
23. 试运行只做同步任务（规格把它写在同步一节）。备份任务没有试运行。
24. 规格文件留在仓库根目录不挪动；计划 1 的第一步把它和这些计划一起做成首个提交。
25. 镜像名先用本地的 `tern:<版本>`，不向任何仓库推送。发布到哪里由你定。
