# tern 计划 6 · 界面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 首次启动向导、登录、解锁，加上规格 §12 的六个页面。全部操作只走 `/api/v1`，构建产物嵌进 Go 二进制。

**Architecture:** React 单页应用。服务端状态全部由 TanStack Query 管理，SSE 事件只用来让对应的查询失效或更新进度，不另存一份状态。基础组件在 `web/src/ui/` 里用 Radix 原语加 Tailwind 自己封装，视觉令牌逐项取自 `DESIGN-notion.md`。Go 侧用构建标签区分“嵌入真实产物”和“占位页”，这样后端测试不依赖前端构建。

**Tech Stack:** React 19、TypeScript、Vite、Tailwind CSS 4、TanStack Query 5、React Router、i18next、Radix UI 原语、Vitest 加 Testing Library。版本以执行时 `npm install` 取到的最新稳定版为准，由 `package-lock.json` 固定。

**Spec:** `2026-11-10-nas-backup-sync-design.md` §12，以及 §6、§7、§9、§10、§11 里涉及界面行为的部分。视觉语言 `DESIGN-notion.md`。执行者同时读 `docs/superpowers/plans/2026-11-10-tern-0-index.md`。

## Global Constraints

索引第 2 节全部适用。本计划另加：

- 运行时依赖白名单：`react`、`react-dom`、`react-router`、`@tanstack/react-query`、`i18next`、`react-i18next`、`@radix-ui/react-dialog`、`@radix-ui/react-select`、`@radix-ui/react-switch`、`@radix-ui/react-tabs`、`@radix-ui/react-tooltip`、`@radix-ui/react-toast`、`lucide-react`、`@fontsource-variable/inter`。开发期：`vite`、`@vitejs/plugin-react`、`typescript`、`tailwindcss`、`@tailwindcss/vite`、`vitest`、`jsdom`、`@testing-library/react`、`@testing-library/user-event`、`@testing-library/jest-dom`。要加别的先问人。
- 不引用任何外链资源。字体、图标、脚本全部打包。页面在计划 1 定的 CSP 下必须能跑：不写内联脚本。
- 所有界面文案走 i18n。`zh.json` 和 `en.json` 的键集合必须完全一致。错误提示按接口返回的 `code` 取文案，取不到时显示 `message`。
- 视觉规则，来自 `DESIGN-notion.md`：
  - 结构色只有 `primary #0075de`：主按钮、链接、激活态、焦点。每个视图至多一个主按钮。
  - 贴纸色只用于状态圆点，不涂按钮和大面积底色。
  - 输入框圆角 4px，不用药丸形。卡片靠细线和极淡的阴影区分，不用重阴影。
  - 唯一新增的令牌是 `danger #d44c47`，只用于失败状态、异常横幅、危险操作按钮。
  - 第一版只有浅色主题。
- 凭据输入：`type="password"`、`autocomplete="off"`；提交成功后立刻从组件状态里清掉。`localStorage` 只存语言偏好。
- 所有时间按节点时区显示（取 `GET /api/v1/system` 的 `timezone`），并在页面上标明时区名。
- 命令：`npm --prefix web test`（`vitest run`）、`npm --prefix web run typecheck`、`npm --prefix web run build`。

## Review Focus

1. **会话过期后点保存** → 跳到登录页并带上回跳地址，登录后回到原页面。不允许静默失败。（任务 3）
2. **弱网下 SSE 断线** → 自动重连，重连后让全部查询失效重新拉取，不停留在过时的“运行中”。（任务 3）
3. **慢网络下双击提交** → 按钮进入等待态并禁用，只发一次请求。（任务 2、6）
4. **两个标签页同时编辑同一个任务** → 后保存的收到 409，提示已被修改、请重新加载，不覆盖。（任务 6）
5. **浏览器时区和节点时区不同** → 时间一律按节点时区显示并标注，cron 预览也是。（任务 3、6）

**Interfaces:**
- Consumes: 计划 1–5 的全部接口
- Produces:

```ts
// client.ts
class ApiError extends Error { status: number; code: string; fields?: Record<string, string>; retryAfter?: number }
function request<T>(method: string, path: string, body?: unknown): Promise<T>
function setCsrf(token: string): void

// types.ts —— 与后端 JSON 一一对应：Status、SSHKey、Connection、Task、Run、UnitResult、Progress、OverviewItem、Settings、SystemInfo、Snapshot、Recovery

// queries.ts —— 每个资源一组 hooks，例如 useTasks()、useTask(id)、useSaveTask()、useRunTask()、useRuns(filter)、useRun(id)、useOverview()、useSystem()

// events.ts
function connectEvents(queryClient: QueryClient): () => void // 返回断开函数

// NodeTime.tsx
<NodeTime iso />        // 用 useSystem() 的 timezone 调 formatTime
```

规则：
- `request`：非 GET 请求带 `X-CSRF-Token`；请求体是 JSON；非 2xx 时解析错误体并抛 `ApiError`，429 时读 `Retry-After`。
- 收到 401 且当前不在 `/login`、`/setup`：跳到 `/login?next=<当前路径>`。
- `connectEvents`：`run.updated` → 让概览、运行列表、该运行的查询失效；`run.progress` → 直接写进该运行的进度缓存；`task.updated` → 让任务列表和该任务失效。连接出错后再次连上时，让全部查询失效。
- `AuthGate` 按 `GET /api/v1/status` 决定去向，优先级从上到下：

| 条件 | 结果 |
|---|---|
| `vault_state` 是 `keyfile_missing` 或 `keyfile_mismatch` | 全屏说明页：密钥文件不见了或对不上，把原来的 `secrets` 目录挂回来再重启。页面上没有任何表单 |
| `setup_required` | `/setup` |
| 未登录 | `/login` |
| `vault_state` 是 `locked` | `/unlock` |
| 其他 | 渲染应用外壳 |

- 语言：默认按浏览器语言，中文系 → `zh`，其余 → `en`；用户在设置页改过就以 `localStorage` 为准。

**Interfaces:**

```ts
// web/src/lib/recovery.ts —— 与计划 4 的 RecoveryRepository 同一规则
recoveryRepository(conn: {username: string; host: string; port: number}, repoPath: string): string
```

**列表**。列：状态圆点加名称、类型、计划（下次运行时间）、上次结果、启用开关、操作（立即运行、试运行（仅同步）、编辑、等价命令行）。右上角主按钮“新建任务”，点开后选备份或同步。

**编辑器**是一张长表单，按下面的分区排列。任务类型在新建时选定，之后不可改。

通用分区：
- 基本：名称、启用。
- 计划：预设下拉（只手动、每小时、每天 03:00、每周日 03:00、自定义）加 cron 输入框。输入停顿 300 毫秒后调 `POST /api/v1/schedule/preview`，下方列出未来 5 次运行时间并标注节点时区；表达式不合法时显示错误。另有：启动后补跑一次（开关）、多久没成功算异常（留空为自动，显示自动值）、最长运行时间（留空为不限）。
- 重试：次数、各次间隔。
- 任务前命令、任务后命令：脚本文本框；执行位置（容器内 / 某个 SSH 连接的远端）；超时；“失败时忽略并继续”只出现在任务前命令。分区底部固定显示一行提示：`能登录这个界面的人，可以通过这里在容器里执行任意命令。`

备份分区：
- 源目录（可增删的列表）、排除规则（每行一条）。
- 仓库：连接（只列 SSH 连接）、远端路径。
- 仓库密码（仅新建）：`生成随机密码`（调 `POST /api/v1/tasks/repo-password`）或 `自己填写`。
- 保留策略：最近 N 个、每日、每周、每月。
- 上传限速（KiB/s，留空不限）、并发连接数。
- 清理周期、校验周期（天）。

同步分区：
- 协议：SFTP、rsync over SSH、WebDAV。下拉下方固定显示提示 `大文件多、网络差，优先选 rsync。`
- 连接：按协议过滤，SFTP 和 rsync 只列 SSH 连接，WebDAV 只列 WebDAV 连接。
- 方向：推（本机 → 远端）、拉（远端 → 本机）。
- 文件夹对：可增删的列表，每行 `本机路径` 和 `远端路径`。
- 删除策略：`只增改，不删除`（默认）或 `镜像`。选镜像时出现 `danger` 色的说明 `目的地多出来的文件会被删除。` 和“单次最多删除”输入框（默认 100）。
- 比较方式：大小加修改时间（默认）、校验和。
- 排除规则、限速。
- 并发文件数：**协议是 rsync 时整个字段不渲染，提交值为 0。**

保存备份任务（仅新建）的流程：
1. 点“保存”不直接提交，先打开“恢复信息”弹窗。
2. 弹窗显示仓库地址（`recoveryRepository` 算出）和仓库密码，有“下载恢复信息”（文本文件，内容是仓库地址、密码、两行恢复命令）和“复制”两个按钮。
3. 勾选框 `我已把恢复信息保存到这台机器以外的地方`。
4. **“确认并创建”只有勾选后可点**，提交时带 `recovery_confirmed: true`。
5. 成功后提示 `已初始化新仓库` 或 `已接入现有仓库`（按 `repo_state`）。`wrong_repo_password` → 错误显示在密码框下方：`这个路径下已有仓库，密码不对。`

其他：
- 字段错误显示在对应输入框下方，键与后端 `fields` 的键一一对应。
- 保存时 409 `conflict` → 横幅 `这个任务已在别处被修改。` 加“重新加载”按钮，表单内容不被自动覆盖。
- “等价命令行”弹窗：`GET /api/v1/tasks/{id}/command-line` 的每一行放进 `CodeBlock`，带复制。
